# Driver Mutation Classifier

A machine learning classifier predicting whether a somatic mutation is likely to sit in a
known cancer driver gene, using only mutation-level features — deliberately excluding gene
identity as an input, so the model must learn a genuine pattern rather than memorize a
lookup table.

## Overview

Not every mutation in a tumor contributes to cancer — most are "passenger" mutations that
came along for the ride, while a minority are "driver" mutations under positive selection.
This project trains and compares two classifiers (Logistic Regression, Random Forest) to
distinguish mutations in known driver genes from mutations elsewhere, using only generic
properties of each mutation: allele frequency, positional recurrence, and functional
consequence class.

**Design constraint (by intent):
(`Hugo_Symbol`) is used only to construct the label, and is excluded from the feature set
given to both models.

## Dataset

| **Cohort** | TCGA-LAML — Acute Myeloid Leukemia, The Cancer Genome Atlas (same cohort as the other MAF-based projects in this portfolio) |
| **Source file** | `tcga_laml.maf`, from [`maftools`](https://github.com/PoisonAlien/maftools) |
| **Usable mutations** | 2,041 of 2,207 (166 excluded for missing VAF) |
| **Label source** | Curated 25-gene AML driver panel, Papaemmanuil et al. 2016, *N Engl J Med* (the clinical/genomic follow-up study to the original TCGA-LAML paper) |
| **Class balance** | 255 driver-gene mutations (12.5%), 1,786 non-driver (87.5%) |

## Features

All features are gene-agnostic — none encode which gene the mutation is in:

| Feature | Description |
|---|---|
| `vaf` | Tumor variant allele frequency |
| `hotspot_count` | Number of other mutations in the cohort sharing the exact same protein change |
| `is_hotspot` | Binary flag: `hotspot_count > 0` |
| `is_silent` | Binary: synonymous mutation |
| `is_truncating` | Binary: nonsense, frameshift, or splice-site mutation |
| `is_missense` | Binary: missense mutation |
| `is_indel` | Binary: insertion or deletion (vs. single-nucleotide variant) |

## Methods

1. Label each mutation by whether its gene falls in the curated driver panel (label only —
   not a feature).
2. Engineer the seven gene-agnostic features above.
3. Stratified 75/25 train/test split (`random_state=42`) to preserve class balance in both
   splits.
4. Train Logistic Regression and Random Forest (`n_estimators=300, max_depth=5`), both with
   `class_weight="balanced"` to counteract the ~7:1 class imbalance.
5. Evaluate with ROC-AUC, precision/recall, and a confusion matrix (threshold = 0.5);
   inspect Random Forest feature importances.

## Results

| Model | ROC-AUC | Driver-gene recall | Driver-gene precision |
|---|---|---|---|
| Logistic Regression | 0.859 | 0.75 | 0.46 |
| Random Forest | **0.894** | 0.75 | 0.43 |

Random Forest confusion matrix (test set, n=511): 383 true negatives, 64 false positives,
16 false negatives, 48 true positives.

**Feature importance (Random Forest):** `is_hotspot` (0.241) and `hotspot_count` (0.238)
dominate, well ahead of `vaf` (0.156) and the mutation-type flags. **Positional recurrence
across independent patients is the strongest gene-agnostic signal of driver status** — this
matches the underlying logic of real driver-detection tools (e.g. MutSigCV,
OncodriveCLUST), and is independent confirmation that the feature engineering captured a
real biological signal rather than noise.

## Limitations & Future Work

- The label itself (25-gene curated panel) defines what counts as "driver" — results have
  not been cross-checked against an independent gene panel (e.g. IntOGen), so the reported
  performance should be read as relative to this specific label definition.
- No real conservation or predicted functional-impact scores (e.g. PhyloP, GERP, SIFT,
  PolyPhen) — these are standard inputs in production driver-prediction tools and were
  excluded here only due to lack of offline annotation resources in this environment.
- Class imbalance handling (`class_weight="balanced"`) trades precision for recall on the
  minority class; the default 0.5 decision threshold was not tuned for any specific
  downstream use case.
- Planned extension: add conservation/impact scores as features, and validate the driver
  gene panel choice against a second independent source.
